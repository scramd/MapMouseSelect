# How tightly this mod is coupled to the game

The selection result needs the game's icons, eligibility rules and selection stores. It does not need to replace the entire map-control frame, modify private input data, or invoke a private clear-all event. Those are implementation choices. Keep the selection adapter and small repairs initially. Loosen input ownership and private UI access in place before considering a larger gesture rewrite.

This study reads the remaining fork, the supplied 0.34.6 client source/assemblies, and the four companion mods. Conclusions about interaction are static deductions, not verified game behaviour. Likelihood below is relative: **high** means private layout or exact instruction shape; **medium** means stable-looking named methods with behaviour assumptions; **low** means an observing hook or public API with little copied logic. Any game update can change them.

The table names every remaining patched member. Unless noted, there are no explicit ordering constraints. Harmony target failures are caught per patch class by Plugin and logged; the rest of the mod can remain partly active. Exceptions from a successfully installed prefix are different: Marquee.Tick and click routing have no exception boundary and can interrupt the native method on every call.

## Coupling without reflection

`SelectionApplier` writes `WeaponManager.GetTargetList()` directly, calls HUD marker select/deselect, native map selection and TargetListChanged. It copies the shape of stock batching but follows map-click eligibility, not stock paint's extra faction/weapon-opportunity checks. Public list availability does not guarantee those writes stay sufficient after an update. A direct member rename causes a build error; unchanged signatures with different invariants cause silent wrong state. A binary built for old field metadata can throw at runtime even if a new build could compile.

The picker reads public icon lists, active state and screen transforms. It relies on prefab geometry and native icon availability. It does not generate missing units. `UnitSelection.DragThresholdPassed` is a gameplay dependency on a mission-editor helper; a rename fails the build. `Unit.MAX_STATION_TARGETS` is a compile-time constant, so a stale binary keeps its old limit.

String contracts also matter: `Cancel`, `Jump Map`, `Pan View`, `Tilt View`, own action names, and `Mouse Button 1/2/3`. A renamed Cancel can stop registration/default writes with warnings. A renamed Jump Map or mouse element name can silently leave camera jumping active on the pan button. Mouse-axis strings changed in IL produce transpiler mismatch warnings.

`BindingBlocker` and CameraJump change public Rewired element.enabled flags and later restore only recorded elements to true. They have no save/copy guards and do not coordinate ownership. Saving/copying maps during suppression could persist disabled native bindings. Whether the UI can save in a particular suppressed context needs a game check. Focus/config/map changes and another mod's reservations can also leave stale ownership. `SystemCursor` uses user32/gdi32 P/Invoke; missing Windows libraries can throw from Move even though Size catches failures. This is platform coupling, not a game patch conflict.

NTL's cloned native pointer component calls Toggle/Set, which requests a delayed native icon refresh. The CheckExclusions postfix reads status immediately; deselection/dimming follows the pane's refresh cadence. It does not rely on a copied OnToggle delegate. Right click only turns NTL on because it is outside stock lists; soloing a stock faction button also leaves neutral filtering independent. Clone initialization can light the Reset indicator through Set even at defaults. Static source cannot prove the clone's pointer hits or screen layout.

## What to keep, loosen or rewrite

These are recommendations, not implemented interaction changes. A visual overlay alone cannot own input; the mod already has a non-raycasting overlay.

| Part | Recommendation | Looser approach with cost and loss |
| --- | --- | --- |
| Broad MapControls skip and press ownership | Loosen in place first | With the default middle pan, the stock pan gate already ignores left. Let MapControls run. Gate competing pan inside own PanButtonCompat while the marquee owns it. Inspect actual native Select bindings before deciding whether a narrow SelectFromMap guard is needed. Require the top EventSystem hit to belong to the map/icon before arming. Cost: runtime input/layout checks and an explicit policy for zoom/waypoints during selection. Preserves more stock behaviour without a whole rewrite. |
| Gesture polling and icon click guard | Consider a later gesture-layer rewrite | Put pointer/drag handlers on a suitable map/icon ancestor. EventSystem raycasts can respect foreground UI and a real drag handler can cancel click delivery. Cost: verify hierarchy, background raycast target, drag propagation, lifecycle and controller design. It may not cover non-pointer action input without a separate adapter. It can remove the Update gesture hook and explicit icon-click patch if proven. |
| Pan button transplant | Keep until interactions are chosen | Narrow gate replacement already touches little IL, but an own pan handler could use native map APIs. Cost: reproducing zoom/scale, follow, clamp and onMapChanged semantics. Losing native pan integration may outweigh removing one call replacement. |
| Pan proportion transpiler | Loosen in place if retained | Preflight all sites and apply as one change, preserving original instructions on mismatch. Longer term use own pan component rather than constants in stock IL. Cost: coordinate math and native notifications; loss of automatic adoption of native pan improvements. Owner can instead drop this optional feature. |
| Native selection adapter and batching | Keep, isolate its assumptions | Centralize all native writes in SelectionApplier. Public SelectUnit/DeSelectUnit calls would reduce copied internals but refresh/play sounds per unit. Own batching can defer one final TargetListChanged across remove/add without changing picking, but needs target/marker and network acceptance checks. No looser solution avoids identifying the game's selection owner. |
| Selected-icon and empty-list repairs | Keep initially | A separate selection hit layer can pick selected icons without changing raycastTarget, reducing the Select action side effect. Cost: hit testing and hover routing. Calling native map deselect from own flows avoids some repair patches but leaves stock Target List exclusions uncorrected. |
| Clear-all event reflection | Loosen in place | In the checked source, the event's only native subscriber is public TargetListSelector.RemoveAll. Call that directly in the postfix and use Harmony __state for per-call count. Cost: the repair then explicitly serves this pane; it would not notify new/third-party subscribers. Check a future native event fix to avoid duplicate row work. No polling reconciler is needed. |
| Rewired registration and default restoration | Replace in the planned bindings step | Use NuclearOption.Bindings and its F1 rows. Cost: migration of saved Controls mappings/unbound choices, menu change from Controls to F1, and own tap/hold state. Loses native Controls integration but removes reflective action construction, private field writes and fixed IDs. |
| Modifier and Jump Map suppression | Loosen ownership in place | Review a shared reservation/save/copy policy or choose interactions that need no conflicting control suppression. Cost: per-device matching, restore on context changes and coordination with Minimap. Additive bindings alone cannot consume native input. Dropping suppression without new interactions restores duplicate actions. |
| NTL UI clone and private theme/reset access | Loosen in place | Clone a unit-type button already carrying the desired theme instead of a faction button; avoid forced private theme callback. Reset NTL in a prefix so native reset greys last. Initialize status without an unnecessary refresh. Cost: verify alternate template layout and native lifecycle; still extends CheckExclusions globally, including HUD selection. An own filter UI/predicate could isolate scope but would need new interaction design. |

The four-mod combination does not justify throwing away the selection logic. Its strongest risk is overly broad input ownership. Start there, then replace input registration in the planned library migration. A gesture rewrite is reasonable if the agreed controller and mouse model needs it; the evidence does not require replacing every part now.

A concrete possible Minimap reservation race requires a user zoom binding on a bare key in ModifierKeys with a native binding. If map-close ordering lets Minimap observe this mod's temporary disabled element before it is restored, Minimap can capture false as the original value and restore false later. This mod then skips an already disabled binding, and a later save could retain it. Minimap keyboard zoom defaults are unbound. This is an ordering scenario from source, not a reproduced conflict.
